hammerBobby
============
+ Řeší duplicitní Content-Type při doplňování výchozího typu těla.
  Stejná chyba byla potvrzena v našem jádru a opravena samostatně.
+ Nabízí statické názvy běžných HTTP hlaviček; nezobrazuje jejich hodnoty.
  Případné převzetí přizpůsobit našemu VariableInput, klávesnici a focusu.

- Import cURL do aktivního requestu v lib/apply-parsed-curl.ts nemaže
  předchozí hlavičky, autentizaci a tělo, pokud je nový příkaz neobsahuje.
  Syntetický test potvrdil zachování starých credentials a těla.
- Po asynchronním parsování cURL se mění právě aktivní záložka. Přepnutí
  záložky během parsování upraví jiný request. Před parsováním se navíc
  maže původní URL; chyba parseru ji neobnoví.
- Export HEAD v lib/code-generators.ts vynechá metodu: skutečný cURL pošle
  GET. URLencoded export nejprve escapuje hodnotu a pak použije
  --data-urlencode: John Doe skončí jako John%2520Doe.
- Apostrofy v URL/hlavičkách/basic auth nejsou správně escapované pro shell.
  Reprodukce používala pouze neškodný apostrof, žádný spouštěný payload.
- Uložení requestu ukládá i celou odpověď do YAML (tělo, hlavičky, cookies).
  To je nevhodné pro kolekce sdílené přes Git.
- Multipart model není sjednocený s CLI (formData proti form_data), CLI
  runner navíc novou reprezentaci nepokrývá.
- Formátování přes JSON.parse/stringify může změnit velká celočíselná ID.
- Nové nápovědy mají nedostatky kolem Shift+Tab, blur a globálního focusu.

Ve změněných testech cURL parseru byly nalezeny údaje připomínající skutečné
credentials. Nebyly přeneseny do našeho repozitáře ani použity pro testy.
Další zpracování dotčeného souboru bylo zastaveno a naše dočasné textové
kopie odstraněny. Tento report jejich hodnoty ani soukromé adresy neuvádí.
Celý parser proto nebyl runtime ověřen. Staticky byly dále patrné problémy
s --form-string/@ a odvozováním metody multipart requestu.

DarkTama
========
+ Užitečný směr: poslední prostředí pro kolekci a kompaktní výběr u Send.
+ Filtry SQLite historie používají parametry a správně závorkované OR.
  Import Insomnia v5 je mimo zamýšlený rozsah našeho forku.

- Starší load prostředí může přepsat nověji vybranou kolekci.
- Dokončení pending load po clear znovu naplní již zavřenou kolekci.
- Runtime override proměnné přežije přepnutí prostředí; například starý
  runtime token pak překryje hodnotu z nového prostředí.
- Volba No environment se nepamatuje, protože null se bere jako absence.
  Paměť poslední volby navíc není persistentní přes restart.
- Přejmenování prostředí na existující název přepíše cíl a smaže původní
  soubor. Syntetický filesystem test potvrdil ztrátu původního cíle.
- storage/environment.rs nadále skládá cestu z neověřeného názvu. Název
  s ../ zapíše mimo kolekci; potvrzeno výhradně v dočasné testovací složce.
  Jde o zachovanou upstream slabinu, ne nově zavedenou traversal chybu.
  Náš společný core stejný vstup odmítá.
- Case-insensitive deduplikace názvů souborové kolize neřeší a může je skrýt.
- Historie má další nechráněné asynchronní odpovědi; runtime ověření celého
  UI historie nebylo provedeno.

CI na prověřeném headu: CLI joby úspěšné, desktop release buildy neúspěšné,
publish-release přesto úspěšný. Existence releasu tedy nedokládá úspěšný
desktop build tohoto headu. Metadata ukazují pád kroku Build Tauri app;
přesná příčina pádu nebyla zjištěna.

sir-geronimo
============
+ Začátek nativního menu a ikony; hotové zapojení akcí ale chybí.

- Patnáct vlastních menu callbacků je prázdných, včetně New, Save,
  Preferences a Toggle Sidebar. Zkratky mohou zabrat funkční Cmd+S/Cmd+N
  bez provedení příslušné akce. About uvádí nesouvisející verzi 0.29.0.
- main.tsx čeká na setupAppMenu před vytvořením React rootu bez ošetření
  chyby. Selhání menu zablokuje start UI; browser dev nemá Tauri API.
- Nový top-level await není kompatibilní s výchozími build targety Vite 6
  v nezměněné konfiguraci tohoto forku. Ověřeno skutečnou transformací
  jeho main.tsx přes esbuild s targety získanými z Vite.
- Skutečný frontend CI padá již na konfliktu verzí pnpm. Nelze proto
  tvrdit, že jeho zveřejněný CI běh spadl právě na top-level await.
- Rust check/test joby úspěšné, nightly buildy neúspěšné. Menu testy nejsou.
- Nové os/opener pluginy a asset permissions rozšiřují závislosti i pro
  nevyužité části menu. Pro malý macOS fork nejsou jako celek potřeba.

Společné rozdíly proti našemu forku
==================================
Všechny tři ponechávají upstream identitu dev.apiark.app, původní globální
data a updater endpoint/klíč. Neřeší naše společné jádro ani hlavní dříve
opravené hranice cookies, skriptů, OAuth a záloh. Licence MIT zůstává.
Naše izolovaná identita, vlastní core a bezpečnostní opravy mají přednost
před případným jednotlivým převzetím UI nápadu.

Reprodukce a limity
===================
Deset reprodukcí přes skutečné TS moduly v Node VM s mockovaným IPC/store,
izolovaným prostředím a syntetickými daty: pět chyb hammerBobby, čtyři
DarkTama a prázdné menu sir-geronimo. Navíc skutečný cURL proti localhostu
potvrdil HEAD->GET a dvojité URL encoding. Rust test nad skutečným modulem
DarkTama potvrdil kolizi při rename a traversal v dočasném fixture.
Transformace sir-geronimo main.tsx potvrdila problém build targetu.

Nejde o kompletní build a ruční test každého cizího forku ani o plný
bezpečnostní audit. Pokus spustit Node proof pod macOS sandbox-exec skončil
před startem; reprodukce následně běžely v běžném Codex sandboxu, s mocky
a bez credentials. Žádná stažená cizí aplikace nebyla spuštěna.

Detailní release log DarkTama automatická kontrola přístupu odmítla kvůli
možnému obsahu privátních klíčů/credentials. Zákaz nebyl obcházen. Pro CI
byla použita metadata kroků, pro podpis přímo zveřejněné binární artefakty.

Naše navazující změny
====================
f119837 — společné jádro doplní Content-Type pro JSON/XML/raw/binary pouze
pokud hlavička chybí. Respektuje case-insensitive explicitní i auth hlavičku
a ignoruje disabled položky. Regrese přes lokální HTTP server: 20 requestů,
kontrola přesně jedné Content-Type hlavičky a nezměněného těla.

Kompletní scripts/check.fish: 113 core + 2 CLI + 1 desktop OAuth + 45 frontend
= 161 úspěšných testů, žádné přeskočené; format, clippy, lint, TypeScript,
frontend build a desktop check úspěšné (stávající clippy upozornění zůstávají).
Nový lokální macOS arm64 .app build úspěšný, přibližně 22 MiB. MIT licence
je přibalená uvnitř aplikace. Distribuční podpis ani notarizace neproběhly.

Ručně spouštěný GitHub workflow pro arm64/Intel je připravený, včetně
kontrol Developer ID, Team ID, hardened runtime, ticketu, verze a architektury.
Má volitelný draft prerelease až po úspěchu obou buildů. Hostovaný běh,
nastavení Secrets, export klíče, přesun repozitáře ani publikace v okamžiku
této kontroly neproběhly. Následně uživatel schválil push forku do veřejného
bckp/apiark a proběhly hostované CI testy a buildy na všech cílových systémech.
